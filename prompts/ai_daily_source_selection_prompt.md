# AI 日报选源编辑规约（event-editorial-v3.1）

现行执行说明见 `docs/SOURCE_SELECTION_LOGIC.md`。本文件描述工作流，逐事件模型契约以 `prompts/event_editorial_assessment.md` 为准，四维权重和阈值以 `config/event_editorial_policy.json` 为准。

## 发现与材料

从 `config/source_registry.json` 启用的聚合源、官方博客/发布日志和论文源召回。AIHot Daily 与 BestBlogs 的推荐是发现和漏选复核信号，不给最终分加权。重要模型更新、官方深度工程实践、聚合站重点推荐应明确留痕。

保留真实发布时间：普通新闻从上次正式发送起，最多回看48小时；研究默认回看72小时；注册源的明确发布补漏最多72小时，断档补漏按原有范围单独标记。候选回流不得刷新发布时间。只以正式发送成功的记录作为已刊去重基线。

新增必须通过novelty_basis引用发布、变更或新研究结果的证据；产品手册功能列表、版本号和被收录日期不能证明新增。

先规范化URL，再归并同一具体事件的不同报道。同公司/同主题不等于重复。读取有界正文并保存证据快照。发现摘要不能冒充已经读过官方正文；材料失败是待核验，不能转换成低内容分。

## 内容评分

只评独立事件：实质变化30%、影响深度与范围25%、目标读者价值25%、认知/方法增益20%。每项0—4级，附具体理由；总分由代码计算并取整。3/4级必须引用输入正文中的逐字证据。未知维度为null。

品牌、类别、聚合分、热度、当天排名不直接加分；官方身份不等于高价值；厂商效果声明要保留范围。不得用当天最小/最大分归一化，不能把当天第一自动变成100。

## 准入与排序

常规路线要求证据足以支持收窄后的表述、具有增量且分数至少60；85起标为深入解读候选。95起必须再读一次证据复核，记录前后判断；同模型第二遍不称为独立核验。60—84分按普通简讯准入，不再要求额外的突出价值维度。低于60分但模型建议报道的条目保留待复核；未知、冲突和评估失败为暂缓。

全部达标的独立事件均可入选：不补足5条、不设置类别名额、不因超过10分钟提高门槛。默认新闻数量无上限，显式调用参数可限制单次输出但需记录暂缓理由。按绝对分降序，同分才考虑真实时效性。

研究/工程事件还要适合机制图解才进入研究池，默认最多1条、允许0条，不为研究位补低分。研究回看候选未获研究位时，不转成过期新闻。

## 发送前复核

重要模型更新、官方深度工程实践、聚合重点推荐及未完成评估的落选候选，必须给出明确的内容或证据理由。只有材料齐全、结构化编辑意见明确exclude、无未解决核验时，完成的模型评估才可提供具名的自动排除理由；它不是人工批准或独立事实核查。建议报道却落选、关键正文缺失、旧记录无结构化意见，均须重新复核。待核验、日期冲突和选中却没写进最终稿的候选要显式处理；禁止只写“分数不足”“条数已满”“篇幅有限”。

最终新闻与研究来源必须映射到当前达标事件；核对评分算术、材料Hash、策略Hash、正文与原文URL，拒绝改稿后夹带未入选条目、重复事件以及利用来源别名绕过门槛。正式发送从2026-09-19起要求v2评估，旧期历史保留。

旧关键词/品牌/类别分仅用于显式历史回放；正式召回和最终入选均不计算这套分数。不得执行旧“至少5条”、70分补位或满分封顶规则。
