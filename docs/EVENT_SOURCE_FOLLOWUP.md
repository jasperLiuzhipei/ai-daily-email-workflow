# 不确定事件的消息源追踪（2026-10-23）

重要新闻的一篇报道不可读或不足以判断时，继续寻找同一事件的其他报道，并沿正文引用追到原始消息源。多篇转载只是发现线索，不是多份独立验证。

## 自动路径

1. 对昨日待补证召回，以及当天原始来源核验未完成的重要候选，使用具体事件/产品名称查询 AIHOT 公共索引。每天最多 4 个查询，每次 20 条；来源日期继续受本期回看窗口约束，分页未读完明确记录部分覆盖。今天核验失败的线索不必等到明天才查。
2. 查询结果作为独立候选进入现有事件归并；同公司或相似主题不直接等于同一次发布。热榜和报道数量不进入评分。
3. 保存可读文章正文中的引用链接。只从实际观察到的链接出发，不猜官网路径，不抓导航和广告链接；优先读取指向具体产品或原文、论文、仓库的引用。
4. 对待补证或明确暂缓判断的事件，允许使用同一已归并事件内其他可读报道的引用。最多追两层引用；仍使用每来源最多 3 个 URL、最多 12 个事件、180 秒恢复预算和总运行预算。已知本轮 403/404 等失败不立即重试，相同 URL 的读取结果复用。
5. 新页面必须通过正文长度、主题与文档身份检查。失败或不相关时保留此前已取得的可读报道，不把抓取失败写成事件低价值。引用到 GitHub 等网站不自动证明官方身份。
6. 原发布公告保留，新增仓库/文档作为补充证据；同一 URL 的相同正文在评分输入中只出现一次。每步记录父页面、链接、深度、读取结果和最终证据地址，再按当前标准重新评估。不能把原报道日期直接复制给无日期的仓库正文，也不修改候选的原事件时间来冒充新消息。

AIHOT 全量、热榜和补证搜索共享 180 秒 HTTP 工作预算。修复了原来从全量抓取开始计墙钟时间的问题：中间处理其他 RSS、官网核验时，不再提前耗掉尚未执行的补证搜索预算。实际 HTTP 耗时记录在 `source.aihot_api.http_seconds_used`。
