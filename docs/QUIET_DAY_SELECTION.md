# 新闻不足时补漏与分级门槛（历史策略）

> 2026-09-30：v3默认关闭按篇数降门槛；改为全天一致的突出价值简讯准入。补源不再依赖不足三条，也覆盖合并事件中未读取的原文。以下记录保留9月21日行为；现行规则见 [选源逻辑](SOURCE_SELECTION_LOGIC.md)。

2026-09-21 用户要求“遇到这种没什么好新闻的情况能不能多补漏，然后降低分数门槛”。本政策替代“任何情况下固定75分”的旧规则；不改变四维评分公式。

## 默认流程

1. 常规入选仍以75分为门槛，深入解读仍为85分。
2. 未刊发回流池保留7天，召回上限从12扩大到24；入池分数改为60分，未完成正文评估的候选也保留。实际发表日期不因召回变成今天，已刊发/明确弃用项仍由历史去重剔除。
3. 常规新闻不足3条时，对待评候选执行一次额外补源、补评：最多12个事件，每来源最多3个已发现URL，共180秒预算，并受原1800秒/650调用总预算约束。
4. 优先使用常规门槛下可补回的新闻；仍不足3条，逐级尝试65分、60分，满足触发数量后不继续下降。增补新闻最多4条，显式新闻数量上限仍生效；不会强行凑满3条。
5. 增补条目仍须有完成的正文评分、可用证据、明确的新信息，且读者价值或认知增益至少3/4。无正文、冲突、重复、明确弃用及低于60分不通过。研究图解资格不因降门槛自动获得。
6. 较低门槛入选的新条目标注“补充观察”；原普通新闻时间窗外但在72小时内的消息标注“近期补漏”并展示原始时间。论文专用回看窗口内容不转换为旧新闻填充。

## 可追溯性

- `event_editorial.quiet_day_recovery`：补源尝试、错误与预算状态。
- `quiet_day_selection`：触发原因、基准及实际门槛、补充事件ID。
- 条目的 `quiet_day_admission`：标签、原始时间、实际门槛和未改变的原分数。
- 写稿后由代码加入标签；最终校验重算准入结果，校验证据哈希，拒绝缺失标签、错误日期或擅改门槛。
- 评分政策哈希仍绑定原评分维度与75分基准，准入政策单独记录，不追改旧分数。

## 补源边界

本版自动重试原文与候选中已发现的替代链接，保留实际取证URL；不假定某个媒体是官方来源。服务器尚未配置通用搜索/浏览器补源服务，因此不能保证从每个403自动搜索出新来源。所有未解决候选继续进入覆盖复核，不因本版降门槛自动关闭待核验项。本机先前为Gemini找到TechCrunch的过程属于人工工具辅助补源。

## 验证

新增行为测试覆盖：先补漏后降门槛、75/65/60分级、增补上限、原分数不变、无正文/冲突/重复拦截、72小时日期边界、403已知备用链接恢复、预算耗尽、实际评分到写稿材料再到最终校验的贯通，以及标题/日期标签完整性。

不改变发送权限、收件人或定时器。部署使用既有哈希检测、备份与失败回滚安装器。
