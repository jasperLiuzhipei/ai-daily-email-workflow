## 已完成的修复

| 原问题 | 当前实现与作用 |
|---|---|
| 选源脚本接近5000行，各职责耦合 | 拆开抓取适配、候选归一、历史去重、分类、输出和命令编排。原入口保留209行兼容接口，实际CLI为649行；本次拆出的最大模块774行。使用显式模块导入，没有运行时拼接执行旧代码。 |
| 新旧评分同时影响正式召回 | 正式召回只准备事实、主题、时间和历史标记，不再计算旧关键词、品牌、推荐加分。旧评分与旧选择器移入 `source_legacy_*`，只有显式历史回放才调用。 |
| 旧权重、最低5条和补位门槛混在正式配置中 | 正式 `selection_policy.json` 删除这些字段，加载时拒绝旧评分配置；历史参数冻结在 `legacy_selection_policy.json`。现行内容评分由 `event_editorial_policy.json` 管理。 |
| 正文提取重复，核验与写稿可能读出不同内容 | 新增共享 `source_document.py`，供来源核验和材料抓取使用；统一去导航和正文区域提取，继续校验写稿材料的摘要值。 |
| 缓存失败后无法恢复、跨期重复抓取 | 正文成功缓存可跨期复用，默认6小时；输入及正文摘要值参与校验。在线重跑会重试失败材料；离线历史回放另行标记。缓存写入采用唯一临时文件后替换，避免并发共用临时路径。 |
| 运行参数变化触发无意义重评 | 评分策略指纹只包含版本、权重、门槛和目标读者；并发数、缓存时长及抓取时间变化不再使同材料评估失效。高分二次复核失败后可重试。 |
| 大候选池缺少总请求约束与观测 | 默认1800秒运行预算、650次模型请求上限；每次调用受剩余时间约束。记录耗时、成功/失败数及网关报告的token用量，接近预算给出标记。评分调用关闭网关内部隐式JSON修复，重试纳入同一预算。 |
| 只有研究不能制作，deep/brief只存字段 | 支持只有研究的期次；深入解读进入重点区，简讯展示事实、重要性与必要边界，不强制升级头条。两类内容都为空时仍停止制作。 |
| 手动覆盖部署难以追溯，容易覆盖服务器已有变化 | 新部署脚本核对目标基线和发布文件摘要值，逐文件备份、替换、验证，失败恢复。此次保留服务器邮件周线程的既有差异，未用本地整文件覆盖。 |
| 无法量化评分质量，容易把模型结果当正确答案 | 新增人工校准模板和统计工具，支持入选准确率、重要事件召回率及重复评分范围；未标注时不输出虚构指标。 |
