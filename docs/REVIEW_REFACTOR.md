# 审核与运行入口整理（2026-10-16）

第一轮重构将公共审核能力从历史自动发送脚本迁出。审核提示词、模型请求、
通过条件、图审回调、重试预算、发送防重和业务配置均保留原有行为。

## 职责

| 模块 | 责任 |
| --- | --- |
| `quality_review.py` | 审核模型协议、来源证据包、文案与图审、绑定图片的审批记录 |
| `workflow_context.py` | 统一工作流路径、输入证据一致性、状态记录；不调度生成和发送 |
| `workflow_cli.py` | 命令参数及默认值；不执行工作流 |
| `run_ai_daily.py` | 调度生成、渲染、打包与发送，保留既有命令 |
| `email_quality_control.py` | 最终邮件审核、缓存、恢复预算和失败通知 |
| `automatic_delivery.py` | 已授权的审核到发送编排，发送前持久化防重复状态 |
| `holiday_auto_publish.py` / `auto_publish.py` | 历史日期窗口和命令兼容入口，复用公共审核 |

当前生产调度继续使用 `publish-reviewed`。旧入口仍可显式调用，其日期限制
保持原样。旧模块导出的公共审核函数、异常类型和主入口的路径工具继续可用；
新生产代码直接依赖公共模块。测试模拟调用应指向实际定义函数的公共模块。

共享模块导入不依赖主运行器、历史发布入口或自动发送编排。正文修复和去重后的
重新渲染仍由运行器承接，未在本轮引入新的调度框架。

最终审核缓存纳入 `quality_review.py` 和 `workflow_context.py` 的实现摘要。
代码变化会使未发送草稿的旧缓存失效，历史 trace 不改写；已发送刊期继续由原有
发送防重逻辑跳过。正常 12～15 条、最多 20 条的新闻规则继续生效。

## 验证与发布

- 迁移函数和命令解析定义与旧版逐项比较，确认只移动职责。
- 全量回归覆盖审批证据、失败记录、局部修复、有限重试、发送前变化和重复发送保护。
- 用已发送两期的真实材料及已保存图审结果离线比较新旧输入、输出与审批记录；不请求真实模型。
- 发布前核对服务器文件摘要，获得工作流锁，备份旧文件，验证失败自动回滚。
- 不更新服务或定时器，不修改业务配置、已发送邮件和发送台账。
