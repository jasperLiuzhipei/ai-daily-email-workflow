# 2026-09-18 选源系统代码审计

范围：正式日报的选源、正文材料、生成桥接、候选回流、覆盖复核、发送编排和相关提示词。不是对工作区所有项目的全面审计。

## 已修复或从默认链路退出

| 问题 | 处理与验证 |
|---|---|
| 关键词/品牌/类别加分堆叠，多个候选挤到100分 | 新增事件正文评分模块；旧分仅留审计，不进入模型或最终准入 |
| 至少5条、低分补位、研究栏必须填满互相冲突 | 默认路径绕过旧选择器；统一75分，允许少新闻、无研究 |
| 抓不到正文被当作内容差，或用摘要继续写稿 | 未知为null、暂缓；发现摘要不能声明已读正文；保留错误 |
| 评分后正文被替换，写稿使用的材料不一致 | 绑定事件、原文、正文与策略Hash；并发抓取层也传播失效错误 |
| 手动改稿夹带低分源，用coverage别名绕过准入 | 最终URL按真正读过且属于达标事件的材料校验，拒绝重复事件 |
| 多源合并丢掉原始入口，造成覆盖复核误报 | 去重时保留来源别名；覆盖匹配与发表准入分开 |
| 原文解析发生跳转后，证据仍记录发现页地址 | 记录实际读取的原文地址并传到最终链接，保留发现入口作为别名 |
| 报纸模板按旧方法类别重排，破坏新排序 | 有事件ID的稿件使用编辑顺序 |
| 待核验分数为null导致候选回流异常 | 回流台账支持null，保留待处理项；排序占位0不回写为内容分 |
| 待核验回流带着旧评估，阻止重新抓正文 | 重新评估阶段显式移除旧写稿保护对象，允许再次取源 |
| 回流时间刷新把旧消息装成新新闻 | 用原始发布时间再次检查新闻窗口 |
| 模型返回1起始证据编号导致有效判断丢失 | 仅对可唯一判断的编号格式归一化，保留原始响应；混合非法编号仍拒绝 |
| 主选源Prompt仍要求至少5条并按品牌加分 | 重写现行规约，更新总控Prompt与README，指向唯一v2评分配置 |
| 两个旧图片测试断言已失效的文案 | 改为验证来自现行统一图像策略的内容；未改图片风格或生图逻辑 |

新增模块将无I/O的校验/准入与网关/缓存分开，避免把全部新逻辑继续塞进旧选择器。

## 首版发布时的技术债

以下为首版审计记录；后续修复和仍待验证的项目见 [技术债修复记录](TECH_DEBT_REPAIR_2026-09-18.md)。

1. **旧选择器仍接近5000行。** 抓取适配器、召回规则、历史去重、老评分和输出拼装耦合。此次只替换默认最终决策，保留 `--legacy-scoring` 供历史诊断。下一步应按抓取/事件/历史记录拆模块，再删确实无调用的旧评分分支。
2. **配置仍有兼容字段。** `selection_policy.json` 与 `daily_config.py` 保留旧权重、76分、70分补位、最低5条；新最终规则只读 `event_editorial_policy.json`。部分旧分仍影响召回和预核验优先级，不等于完全脱离历史启发式。应在历史回放迁移后移除这套双轨配置。
3. **抓源还不是零失败。** 今日样本5项未取得足以评估的正文。不同抓取器的正文提取和URL规范化有重复实现；动态页面、导航正文误判和日期冲突仍须逐源改进。现在失败可见，但尚未解决所有站点。
4. **事件归并与内容判断依赖模型。** 输入校验只能防止越界引用、重复组和算术错误，不能证明语义判断正确。同模型二次检查不是独立验证。缓存保证同快照回放，不保证换模型或重跑判断一致。
5. **75/85/95尚未完成历史校准。** 本次是24来源样本验证，不能据此宣称漏选率/准确率已经改善到某个比例。需用人工标注样本衡量重要事件漏选、低价值误入、同事件重复和边界分数漂移，再调整权重。
6. **大池评分耗时与成本待量测。** 有并发、单源长度、请求重试和300来源容量约束；目前尚无跨期共享正文缓存、完整阶段时间预算和运行成本告警。不要把300来源容量理解为300条都能快速完成。
7. **展示和发布还存在边界。** deep/brief未完全控制模板篇幅；只有研究没有新闻时仍停止整期。正式门禁在统一编排入口，底层SMTP脚本不是通用不可绕过的发布权限系统。
8. **本地与服务器已有版本漂移。** 比对发现邮件周线程处理、本地中台影子文档及部分测试在两端并不相同。本次部署对编排器使用本次差分，记录文件Hash和备份；没有借此次更新替换这些既有差异。应另行建立可追踪发布版本与一致的测试基线。
