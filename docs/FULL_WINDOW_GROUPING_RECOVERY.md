# 全量选源中的局部失败隔离

2026-10-23 的 08:30 完整回放发现：544 个来源的两次模型分组各返回 42 组，分别有 1、2 个来源 ID 跨组重复。旧实现因此把所有分组合并都作废。另一个问题是 4 次待核验补源搜索全部被热点占用，历史待核验召回没有获得搜索机会。

## 修复边界

- 保留原来的两次分组尝试和严格校验。两次都失败时，仅保留结构合法、来源 ID 已知、与响应中其他组完全不重叠的组。
- 跨组重复 ID 涉及的所有组都隔离，相关来源仍独立进入后续评估；不选择其中一个组，也不猜测合并。未知 ID、重复 ID、理由不足和畸形结构同样不接受。
- 记录保留组数、拒绝组索引和冲突 ID。分组缓存键加入恢复版本，防止沿用旧的整批作废缓存。
- 在固定的补源搜索总预算中，先为 `pending_evidence` 历史召回预留一半去重后的查询。剩余名额沿用热点优先顺序；没有待核验召回时全部名额仍可用于当前线索。

评分提示词、权重、门槛、研究/新闻版位、补漏上限和发送授权均不改变。这些措施只控制检索与分组失败的影响范围，不能保证任何指定新闻入选。

回归见 `tests/test_grouping_recovery.py`；包括真实运行入口在两次分组失败后保留有效组，以及热门线索不能耗尽全部待核验搜索预算。
