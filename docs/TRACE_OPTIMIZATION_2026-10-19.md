# 采集、审核输入与 trace 计数优化

2026-10-19 的日报已正常发送。本次只更新后续运行使用的代码，不重写该期正文、审核历史、图片、名单或投递记录。

## 来源传输

DeepMind 当天的 RSS 文件以 gzip 魔数开头，却被直接当作 UTF-8 解析。采集器现在让 curl 协商并解压标准压缩响应；响应缺少 Content-Encoding 时，再按 gzip 魔数解压，然后保存解压后的原始 XML/HTML。解压最多 32 MiB，损坏压缩流记为抓取失败。HTTP 4xx/5xx 不再被视为成功正文，沿用现有请求次数和超时预算。

用当日保存的 18,396 字节响应重放，可以解析 100 条 RSS 记录。该响应中没有落在当期新闻窗口内的条目，因此修复解析不等于今天确认漏报了 DeepMind 新闻。

## 文案审核输入

最终文案审核使用独立的紧凑证据投影，完整保留既有正文范围、摘要、不同来源的逐字引文、URL、可读状态、证据角色、截断标记和可引用的短标识。仅去掉长哈希、重复的 provenance.supporting 列表和来源/引文/可读状态完全相同的重复记录。不合并不同来源，不把摘要提升为原文，不减少证据文本。

投影前仍校验已选事件的输入指纹和引文；完整证据保留在审核记录所绑定的 source_material 和 source_selection 中。内容生成与旧证据接口保持原格式。最终审核提示词说明长哈希保存在归档材料中；通过条件、审核模型、重试次数和发送门禁保持不变。代码和提示词变化会自然使旧草稿审核缓存失效，历史审核文件不改写。

当期 16 条材料离线回放：完整请求从 310,512 字节降至 256,234 字节，减少 17.48%。这是字节测量，不是 token 用量估计。

经明确授权，另用原审核模型 `gpt-6-sol` 和相同请求参数对压缩材料做了一次独立复审。API 返回的实际输入 token 从 91,584 降至 65,702，减少 25,882（28.26%）；总 token 从 91,846 降至 65,911，减少 28.24%。六项审核检查仍全部通过，阻断问题和修复要求为空；原先一条可选日期建议本次未出现。

复审结果独立保存，未启动发布或发送流程。16 条材料的正文、摘要、引文与来源归属逐项一致，361 个受保护的日报文件及投递记录前后哈希一致。本次对照支持该期审核结论一致，不代表所有后续期次的审核效果已经得到统计验证。

## 计数语义

事件评估摘要增加三个字段：

- `assessment_completed`：完成结构化评估的事件数。
- `assessment_pending`：尚未完成评估的事件数；不能直接视为接口调用失败数。
- `editorial_deferred`：已完成评估，但准入判断仍为暂缓的事件数。

`assessment_completed + assessment_pending = event_count`。为兼容旧读取方，保留 `completed = assessment_completed`，以及旧 `pending = assessment_pending + editorial_deferred`。新展示和分析优先使用明确字段。

当期重放结果：73 已完成、37 待评估、47 已评估但暂缓；旧 pending 仍为 84。此变化只解释计数，不改变评分、候选排序、入选内容或补源预算。

## 验证

回归覆盖正常/缺头 gzip、损坏压缩流、HTTP 失败及有限重试、完整证据归属和截断边界、空评估与混合状态计数。额外以当期已保存的来源和审核输入核对正文、摘要和引文逐项相同。测试不触发日报生成或发送。
