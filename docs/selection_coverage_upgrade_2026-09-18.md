## 生效规则

- 新闻数量由质量与独立信息增量决定。取消默认12条封顶、同主题名额及超过阅读预算后的额外抬分；不再达到5条就停。阅读时长保留为提示，事件去重和时效检查继续执行。
- 高价值候选先核验官方正文，再最终评分。分别记录未尝试、未读到正文、已读到正文；抓取问题不再额外触发模型69分惩罚，也不能获得未经核验的证据加分。
- 新增 GitHub AI 官方RSS；修复将作者简介误识别为正文的问题。Qwen 动态博客使用其公开文章API读取正文。旧研究补漏稿保留研究路由，避免混入当日新闻。

- 最终正文缺少上述高价值条目时，必须补选或逐条记录排除/延期原因。仅写“分数低”“篇幅限制”不能通过。官方日期冲突也需明确处理。未解决时阻止正式发送；修改来源或评分会使对应旧决定失效。
- 用户随后明确：取消条数上限不取消76分入选门槛。复核是重新检查价值与证据，不是强制补入；低分默认留在候选池。补源或纠正分类后必须记录证据及重评结果，过线才入选，不能给预定入选结果倒推分数，也不能借用不同来源的高分。

## 复核入口

使用 `ai_daily_workflow/scripts/coverage_review.py`，输入当期选源JSON、最终正文JSON和复核JSON路径；报告输出同名Markdown。每条落选需指定 `--item-id`、`--disposition`、`--reason` 和 `--editor`。发送入口会自行刷新并检查报告，不能只改顶层“通过”标记。
