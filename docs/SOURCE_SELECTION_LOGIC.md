# 现行选源、评分与入选逻辑

更新：2026-10-23。引擎：`event-editorial-v3.1`。本文描述已经接入 `run_ai_daily.py select/prepare` 的实现。它与 `daily_v2` 中台影子工作区不是同一个版本概念。

## 1. 先召回，再判断价值

注册表现有23个启用条目，包括聚合发现、官方直连和原文解析角色，并非23个都独立全站扫描。

| 层次 | 当前来源 | 用途 |
|---|---|---|
| 聚合发现 | AIHot 分页全量 API、热榜多源回查、主/论文 feed、Daily；BestBlogs 高分 AI feed | 扩大召回，发现值得复核的遗漏 |
| 官方直连 | OpenAI、Anthropic/Claude、DeepMind/Google Research/Developers、Microsoft Research、Meta、Hugging Face、Z.ai、MiniMax、Kimi、Gemini API、DeepSeek、GitHub AI 工程 | 获取实际发布与工程实践 |
| 论文 | 有界 arXiv Agent/评估相关查询，以及聚合条目的原文链接解析 | 论文与方法发现，不全量扫描 arXiv |
| 未刊候选回流 | 最近4日未实际发送的候选，最多回流24条 | 追踪写稿失败、待补正文和未刊高价值项；原始发布时间也必须在96小时内 |

AIHot 推荐、BestBlogs 分数和重要模型名单用于发现及漏选复核。它们不是最后的日报分数。正式召回不再计算旧关键词分、品牌分和推荐加分。主题识别、时间窗口和历史去重仍有启发式规则；旧数值评分仅保留在显式历史回放模块。

2026-10-10 起，所有选源路径的最大回看范围统一为四天（96小时），以本次选源截止时间 `end_at` 为基准，由 `selection_policy.freshness.max_lookback_hours` 控制。发送断档时仅接续最近四天；普通新闻的较短窗口默认48小时，研究发现默认72小时，部分官方源保留72小时补漏，均不能突破统一上限。手动扩大新闻或论文窗口也遵守上限。未刊候选按原始发布时间过滤，重新出现或生成草稿不会刷新其日期；研究回看材料未获研究位时，不能改成过期新闻补位。

## 2. 以独立事件为单位

先合并同一规范化原文 URL，再用文本模型识别不同 URL 是否描述同一具体发布、论文或事故。只接受输入中的来源 ID，禁止重叠分组；拿不准时不合并。

同公司、同主题、同模型的不同版本不因此互相挤掉。合并后保留来源别名用于覆盖复核，但这些别名不能用来给任意最终链接放行。正式发送成功的历史才作为已刊基线。

## 3. 内容分和证据状态分开

每个事件取得有界正文快照后，模型先写清“新增了什么、读者得到什么、证据局限”，再评四项0—4级：

| 维度 | 权重 | 主要问题 |
|---|---:|---|
| 实质变化 | 30% | 相对已有能力、成本或工作方式，到底改变了什么？ |
| 影响深度与范围 | 25% | 影响哪些工作，有多深、多久？ |
| 目标读者价值 | 25% | 对产品、研发、运营和内部AI提效有什么具体价值？ |
| 认知或方法增益 | 20% | 有什么可迁移的方法、证据或值得修正的认识？ |

先按有明确归属、证据支持的收窄表述评新闻价值；厂商自报、模拟测试、未独立复现等限制写入证据状态及边界，不能重复充当全面降分理由。产品手册功能列表、截图版本号和聚合收录日期不能证明新增。`novelty_basis`须绑定发布、变更或新发现的逐字证据。

总分由代码计算：`round_half_up(Σ 等级 × 权重 / 4)`。0是无实质价值，2是明确但有限，3是有依据的实质价值，4需要达到最高锚点。未知为 `null`，不是0。数字只是编辑量表，不是成功概率；一分差距不代表统计显著。

3/4级判断必须引用输入正文中的原句；代码检查来源 ID、逐字引用、维度和算术。官方身份、品牌、热度、推荐排名和类别不直接加分。论文和工程文章使用同一量表，不再各有一套容易封顶的分数。

证据另分为：

- `supported`：正文足以支持收窄后的表述。
- `limited`：可发表带明确限制的表述，例如厂商自报、摘要或单个案例。
- `unresolved` / `conflicting`：材料不足或核心冲突未解决，暂缓。

读到官方发布不等于其效果已经独立验证。只有聚合摘要、HTTP失败或模型调用失败时，保留待核验记录，不按低价值处理，也不拿旧分数补位。

## 4. 常规准入与突出价值简讯

| 条件 | 当前处理 |
|---|---|
| 证据可用、有新增信息、编辑建议报道、分数≥60 | 可入选简讯 |
| ≥85 | 标记为深入解读候选 |
| ≥95 | 先做第二遍正文复核；保留前后分数与理由，再决定入选 |
| 60—84 | 按普通简讯收录，不再要求额外突出价值条件 |
| <60 | 模型建议报道则待复核；明确低价值则落选 |
| 分数未知、证据冲突、评估失败 | 暂缓，待补材料或复核 |
| 无独立新增信息 | 落选 |

95分的复核目前可以由同一个配置模型第二次完成；记录明确标记它不是独立事实核查。

2026-09-30用户进一步要求降低门槛：普通新闻统一60分，85分以上进入深入解读。此前60—74分的突出价值例外只用于历史策略回放；当前不要求额外最高等级。低于60但明确建议报道的候选仍进人工复核，不能仅以分数删除。

达标后再执行常规 12–15 条、最多 20 条的新闻篇幅预算。候选不足可以少发；常规高价值补漏最多 2 条，另外最多 2 条头条级补漏可在总量内参与竞争；先比较优先级，再兼顾同类覆盖。被篇幅限制的候选保留暂缓理由和召回机会。10分钟阅读预算只提示。详见 [篇幅预算](NEWS_VOLUME_BUDGET.md) 和 [覆盖与补漏](SOURCE_COVERAGE_RECOVERY.md)。

2026-10-23 起默认启用独立 `publication_priority`：新闻先排头条候选、重点、普通，同档再按原综合分、有明确后果的时效性和稳定事件 ID 排序。高优先级必须引用可读证据、说明实质影响，不能凭品牌、热度或报道数量升级，也不能绕过上述准入。头条候选可使用展开档位；研究位置仍按原综合分选择。研究或工程事件还需适合机制图解，默认最多1条，允许0条；图解位不拉低质量线。支持只有研究、没有新闻的独立期次；两者都没有达标事件时停止制作并保留候选，不补填。

`deep/brief` 已用于报纸版展示：深入解读项进入重点区，简讯展示事实、重要性和必要边界，不自动升级为头条。生成模型仍产出结构化字段，模板按层级决定展示范围，不按分数机械截断句子。

数量和排序随当天候选变化，绝对内容分不随当天分布漂移。优先级拆分及固定样本结果见 [优先级验证](PUBLICATION_PRIORITY_EXPERIMENT.md)。权重与门槛需要积累人工反馈再校准，不自动每日调参。

## 5. 写稿和发送不能绕过选源

写稿复用评分时的正文快照，同时带入价值判断和局限。正文、原文 URL 或材料 Hash 改变后必须重评；材料校验失败不降级到摘要，也不再调用旧研究补位逻辑。

2026-10-12 起按用户要求，终审只处理已选正文与图片，不再进行全候选覆盖复核；发送继续使用现有的自动运行策略。2026-10-23 新增的热榜覆盖回执放在上游选源阶段，帮助追踪未采到、待补证与暂缓原因，不新增发送审批。

正式生产入口仍要求事件评估、原文证据绑定和最终来源校验；最终新闻与研究 URL 必须属于已通过准入的事件，来源别名不能绕过校验。历史已发送期次按存档策略回放。

## 6. 实现与审计文件

- `config/source_registry.json`：发现源和抓取角色。
- `config/selection_policy.json`：正式发现、时间与复核策略；禁止混入旧评分字段。
- `config/legacy_selection_policy.json`：冻结的历史评分配置，仅用于 `--legacy-scoring` 回放。
- `config/event_editorial_policy.json`：现行四维权重、60/85/95门槛、新闻优先级契约、并发及容量。
- `prompts/event_editorial_assessment_priority.md`：当前等级锚点、证据及独立新闻优先级输出契约；原 `event_editorial_assessment.md` 保留历史兼容。
- `scripts/event_editorial.py`：纯校验、算分、准入与排序。
- `scripts/event_editorial_runtime.py`：配置网关、正文、缓存、并发和失败留痕。
- `scripts/coverage_review.py`：保留的可选覆盖复核实现；当前全候选终审关闭。
- `scripts/aihot_discovery.py`：分页发现、热榜/待补证来源回查和选源覆盖回执。

每期 `event_editorial/` 保留分组输入、正文快照、原始模型响应、错误、分数及理由。选源 JSON 记录实际策略和证据 Hash；同正文、提示词、模型和评分策略的缓存可回放；抓取时间及并发数变化不再导致重评。重新调用模型仍可能给出不同判断。

资源边界：默认4并发，最多600个规范化来源，正文每源最多12000字符。超容量明确失败，不静默截掉尾部。正文成功缓存默认有效6小时，可跨期复用；失败材料在线重跑时重试。评估预算默认1800秒、最多650次请求，每次输出耗时、请求成功/失败数和网关报告的token用量。接近预算时标记warning；预算耗尽不再启动模型请求，未完成事件暂缓。货币成本不在缺少价格数据时猜算。

初始验证见 [今日样本验证](event_scoring_validation_2026-09-18.md)；剩余结构性问题见 [代码审计](CODE_AUDIT_2026-09-18.md)。当前不是完成14天标注回测后的最终校准版。

模块职责、修复范围与本次部署验证见 [技术债修复记录](TECH_DEBT_REPAIR_2026-09-18.md)。

## 7. 2026-09-30迁移与验证

评分政策使用`admission_contract=value-evidence-v3`；策略和提示词变化使旧模型评分缓存失效。历史正式已发送期次仍按其存档策略验证。关闭按当日篇数逐级降低门槛的默认开关；突出价值路线全天一致，不依赖是否已有三条。补源独立于新闻数量，覆盖部分正文缺失的合并事件，仍有12事件/3链接/180秒边界；首轮评分预留最多180秒且不超过总预算四分之一。失败记录保留具体fetch_error、未尝试事件和材料缺口。

`replay_editorial_packets.py`对冻结正文做隔离模型重评，不发送邮件、不覆盖旧分数。历史分数、编辑标签不进入模型输入。仅用已存材料回放不能证明HTTP故障已修复，也不是完整长期人工校准。实施与验证见`SCORING_REPAIR_2026-09-30.md`。
