# 日报正文编辑与发送校验

正文的任务是让读者理解新变化及其意义。简洁是去掉重复和旁枝，不是把研究解读、重点解读一律改成短讯。正文必须独立讲清主要问题、机制、相互独立的核心发现及其证据，不能把关键解释全部留给图片或原文。完整性不等于穷尽原文章节：同一结论的多种模型排名、指标读法和辅助分类可以择取代表性证据；审稿不能把这些都列成必须补回的清单，也不能让启发段承接溢出的数据。

## 实际入口与规则职责

- `prompts/api_research_system_prompt.md` 同时生成正文和图解交接，两者都保留理解主贡献所需的机制、证据与边界。研究正文不设固定最短字数，也不按数字数量删除发现；生成后依据来源做一次语义审查，遗漏和确实妨碍阅读的冗余一起进入有限改写。图解仍按 `docs/IMAGE_WORKFLOW.md` 独立处理。
- `prompts/api_daily_content_system_prompt.md` 是单条新闻、批量新闻及编辑简评的共同编辑规则。`--system-prompt` 的实际文件及哈希记录在生成元数据中，避免修改文档却没有作用到服务器运行路径。
- `scripts/daily_prose.py` 是生成阶段和最终校验共用的正文检查。字符按非空白 Unicode 计数，英文、数字和标点均计入。预算用于触发有来源的编辑改写或阻止发表，禁止用字符串截断满足预算。
- 新闻生成必须保留来源的 `event_id`、`display_tier`、`daily_rank`。`display_tier` 是选源深度评分结果，不能直接决定栏目是否存在。
- `scripts/newspaper_sections.py` 在生成前确定 `newspaper_role`（lead / supplement / brief）。显式编辑安排优先，否则 deep 候选优先并按选源顺序补足重点解读、重要补充；不会改动评分、选源层级或事件顺序。历史修订可以显式绑定原刊的两栏选题。重复或缺失的显式重点角色要求重新编稿，不能悄悄删栏。
- 重点解读、重要补充使用充分的正文空间，交代变化、原因或机制及独立启发；其余简讯没有新判断时可不填工作启发。研究与重点的字符阈值只负责拦截极端长稿，不能替代信息完整性审稿。

## 内部核验备注与读者提示

来源的 `editorial_assessment.limitations` / `boundary` 是写作约束，不能直接复制到最终 `boundary`。生成器应把确实影响理解的条件写入摘要或简短边界，例如测试版范围、厂商自报、二手归因及指标口径。材料抓取、网页导航、编辑待办等保留在内部记录。

省略读者边界时，生成器记录仅供诊断的处理理由，区分“限定已在摘要中”与“纯内部备注”。不得为缩短正文把真实不确定性归为内部备注。检查技术文章时，不能把“处理用户提供的正文”“返回完整 JSON”等真实机制误判为编辑指令。

## 生成、构建与发送

1. 新闻生成对长稿、明显重复或内部备注做有限编辑修复；研究初稿还需来源语义审查，既检查核心贡献是否缺失，也检查旁枝堆砌。不能因机械数字计数删掉独立发现，不能发布截断的句子或回退为来源摘录。
2. 构建前检查全部将被显示的文字，兼容旧研究字段与证据列表；空 `research_items` 回退到 `paper` 时同样检查。
3. 报纸排版保留简讯层级，并将正文、编辑简评等可见字段签名与 HTML 哈希一起写入 normalized 内容。
4. 正式发送即使使用 `--skip-build` 也重新校验正文，并核对原始稿、normalized、HTML 及选源/材料之间的绑定。缺构建签名、正文已修改但仍使用旧 HTML，均要求重新构建。图片清单必须覆盖每篇实际渲染的研究，不能漏验第二篇或被空 `research_items` 绕过。
5. 研究缓存只有成功生成后才写入 `.cache.json` 凭据，绑定来源、实际系统提示词、生成器与编辑规则及四份输出。复用前、新生成后均检查；发起刷新即撤销旧凭据，失败不能靠残留文件或相同 raw 响应冒充成功。旧版缓存需用 `--refresh-api-content` 重新生成，不改历史已刊文件。
6. 自动发布与手工正式入口共用当前正文与栏目规则，不再保留 12 条硬上限或要求简讯填写重复启发；自动发布原有独立质量审核仍执行。

历史已发送内容与投递台账保持原样。回放必须使用独立 `tmp` 或 `output` 目录；不得把目录命名成生成日期后触发台账同步。真实 API 验证仅发送经检查的公开来源材料，内部收件配置与投递记录不进入模型请求。

## 回归检查

重点运行 `test_daily_prose.py`、`test_research_prose_recovery.py`、新闻编辑测试、`test_newspaper_sections.py`、`test_prod_prose_gate.py`、`test_newspaper_text.py`、`test_newspaper_illustrated.py` 与 `test_high_value_coverage.py`，并确认真实生成的栏目、重点选题、解释深度、数量、限定保留和可读性。整期验收不能只看字符变少和零溢出。部署器默认回归现已包含这些正文与发送检查，以及用户认可样稿的 `test_approved_editorial_v2.py`，不再只验证选源模块。样稿约束与复查入口见 [EDITORIAL_ACCEPTANCE_V2.md](EDITORIAL_ACCEPTANCE_V2.md)。

正文规则只提供可重复的最低保障；字符数合格不等于事实核对或编辑质量已经全部合格。
